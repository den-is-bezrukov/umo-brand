# umo-brand

React + Vite + Tailwind CSS site for UMO brand materials: the brand guide at `/`, the price-card poster generator at `/price-card` (web preview + print-ready PDF export), the dealer livery generator at `/livery` (car preview + cut files), the number plate frame generator at `/plate-frame` (the strip printed under the plate, as a PDF) and the name tag generator at `/name-tag` (staff badges, as a PDF). Deployed to `umo.autos` via GitHub Pages on every push to `main` (`.github/workflows/deploy.yml`).

## Development Server

Nothing runs automatically — start it yourself:

```bash
pnpm dev
```

This serves the app at `http://localhost:8443` (port set in `vite.config.ts`, not the Vite default). Hot reload is on; changes to source files show up immediately.

`pnpm dev:follow` (`scripts/dev-follow.mjs`) does the same and also pulls the current branch every 10 seconds (fast-forward only, reinstalling dependencies when the lockfile changes), so changes pushed to it show up in the open page without touching the terminal.

Icons in `public/` (Figma fav 4870:3556): `favicon.svg` and `favicon.ico` are the U module of the logo, white on a black tile — the full wordmark turns to mush at 16px. ## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. This scaffold does not need a Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults there.

## Brand guide (`/`)

`src/guide/Guide.tsx` is the web version of the UMO brand guide page from Figma ([UMO | Evrone, node 4810:686](https://www.figma.com/design/i6PdEDo72Vab0cAixG0nIz/UMO-%257C-Evrone?node-id=4810-686)). Text and layout are live code; every illustration is a Figma frame exported at 2x and saved as `src/assets/guide/<name>.webp` (cwebp `-q 90`), picked up automatically by `import.meta.glob`.

To refresh an illustration, re-export that frame at 2x and overwrite the file with the same name. Export the whole section Block and crop the frame out of it: frames that stretch inside a grid/flex parent come out of Figma's direct export at the wrong size (a mostly empty canvas).

Vector schemes (clear space, minimum size, co-branding, type specimens, model lettering) are SVG files in the same folder — `img()` prefers `<name>.svg` over `<name>.webp`. They are cut out of Figma SVG exports of the parent Body nodes by `scripts/split-figma-svg.py` (node ids and crop boxes are listed at the bottom of the script). Text inside them is outlined by Figma. The lettering pictures (`lettering-model8` / `lettering-model5`: MODEL lettering over its number plate) are laid out by the script's `assemble()` from separate layer exports instead, as those frames export stretched. Photos, logo misuse examples, app/social icons and model posters stay WebP.

The UMO 5 / UMO 8 ad banners in Ключевой образ are `Poster` components: a photo-only background (`<model>-<banner|square>-bg.webp`, about 3x the Figma frame) with the title, subtitle and `UmoYandexLockup` laid over it in container-width units, so text and lockup stay sharp at any size. The backgrounds were cut from the source photos using the layer geometry in Figma; the direct export of the banner photo layers is broken the same way as stretched frames.

Body copy (`Text`) takes its width from its length on the 12-column Figma grid: up to 150 characters 6 columns (432px), up to 300 — 8 (600px), longer — 9 (678px). Don't set widths by hand; texts paired side by side sit in a grid with `*:max-w-none` and fill their cells.

Vertical rhythm is fluid: `--spacing-section` (96px on a 375px phone → 216px at the 1440px Figma frame) and `--spacing-chapter` (144 → 288px) in `src/index.css`, used as `gap-section` between sections and as the extra top padding of a `Chapter`; don't hard-code breakpoint gaps between blocks. Each chapter is a `Chapter` (id, title, then its `Section`s). A section's opening picture goes above its heading, with the section anchor on the picture (Позиционирование, Фотография). Chapters stay two levels deep — chapter, then its sections. Пространства holds the brand's physical places (for now its intro with the dealership photo; the Дилерский центр section is drafted and commented out in `Guide.tsx`); Носители (anchor `materials`) the templated media (Ливрея, Прайс-карта, Рамка номера, later leaflets and the like), as Porsche splits Spaces from Analog media. Anchor ids sit on an empty marker above the title, so keep new chapters inside `Chapter` rather than a bare `<h2 id>`. Links to the guide have gone out, so when an anchor id changes, add the old one to `OLD_ANCHORS` in `Guide.tsx`: it is redirected to the new id on load and on a hash change.

The first screen follows Figma 4893:3846 and 4897:4565 (prototype 4921:2352): on `lg`+ the hero (`Hero` in `Guide.tsx`) is fixed full-width behind the page, which starts a strip above the bottom of the screen (`--strip`, set by `useHeroStrip`: 286px at 1440), so the first screen shows the photo, the 200px logo, the «Содержание» row, the statement and the quick links under it (Стандарты → `#positioning`, the way into the whole guide from its first page, which lands its picture 24px under the top of the screen from `lg` — `lg:scroll-mt-6`; Носители → `#materials`, 48px below the statement; no link to the official site); scrolling, the page slides up over the photo. The sidebar's toggle row is fixed to the bottom of the screen (CSS, not script: moved by script it lagged the scroll a frame and shook); until the page docks at the top, `useHeroReveal` fades the contents in over the first 160px of scroll, so they unroll between logo and row; the photo stays still (no parallax: it cheapened the curtain), the logo shrinks with the scroll from 200px wide to its usual 120 (24 high) by the time the page docks, and the row does what it says anywhere, on the first screen also scrolling the page up to the top. The logo scrolls smoothly to the very top (`toTop`), photo included; «Платформа бренда» lands the page's top edge at the top of the screen (`lg:scroll-mt-[calc(24px-0.164em)]` on the statement, the body's padding above it plus its own margin), so no strip of the photo shows. The statement is aligned optically by CoFo Sans's metrics: the body's 16px on top plus `lg:mt-[calc(8px-0.164em)]` put its capitals level with the top of the logo at any size, and the strip is sized so the quick links share a line with the toggle row, however many lines the statement wraps to. Below `lg` the film is simply the first thing on the page, above the header, and takes what the first screen has left above the header, statement and quick links (`--mstrip`, measured by `useHeroStrip`) and the bottom bar with a gap over it, so the first section of the guide starts below the fold; it is never less than half the screen's width (a phone held sideways). The hero is the UMO test-drive film (source `02 UMO/Site Video/Test Drive/` on Yandex Disk), looped and muted: `src/assets/guide/hero.mp4` is `UMO_test-drive_1080.mp4` byte for byte (H.264, 12 MB) and `hero-720.mp4` is `UMO_test-drive_720.mp4` (1280×720, 6.2 MB), both already fast-start and silent — don't re-encode them, they were set up by hand — with their first frame as `hero-poster.webp`. The 1080p plays by default and the 720p on a slow connection: at once where the browser reports the speed (Network Information API in Chrome, Edge, Android: `effectiveType` 3G or slower; not `downlink`, which Chrome guesses from the first requests and reads far too low then), and in any browser (Safari has no such API) when the 1080p hasn't buffered enough to play 3 s after the page opens. It plays only while some of it is on screen, stopping once the page has slid over it whole and going on from that frame when it shows again; with reduced motion or data saving on, the still `hero.webp` (woman by UMO 8) stands in. CI and the deploy fail on any video over 15 MB. Navigation follows Figma section TOC (node 4865:1079). The hero at the top of the page is not in the list: the logo leads there. Платформа бренда (the brand foundations: positioning, vision, mission, audience and voice) has no title of its own: the statement under the hero («Автомобильный бренд, созданный в технологическом партнёрстве с Яндексом»: from `lg` 60px in the 912px Figma column, scaled with the column below that — `min(60px, 6.58cqw)` — so it wraps the same three lines at any width; no «UMO —»: the logo stands right beside it) stands in for it and carries the `brand` anchor, so it isn't a `Chapter`. On `lg`+ the sidebar lists chapters with only the one you're reading open; the space between items is the links' own padding (chapters 8px above and under, items 4px, the last item of a chapter 8px under it), not gaps, so the whole list is clickable with the same rhythm as before (Figma 4865:1031), and the list's -8px top and bottom margins tuck the first and last chapters' padding under the logo and the toggle row (4865:1025); the «Содержание / Свернуть» row (`TocToggle`, menu and cross icons from `src/icons/toc.ts`, the same as on the mobile bar) is pinned to the bottom of the screen, so it doesn't move as the open chapter changes the list's height. The choice is remembered in `localStorage`. When the list is taller than the screen, the sidebar scrolls itself to keep the item you're reading in view (`useActiveInView`). Below `lg` the header holds just the logo; a bar fixed at the bottom shows a menu icon and the title of the heading you're reading (any level, from `NAV`; «Платформа бренда» on the hero above it) and opens the full, expanded contents between header and bar, with «Свернуть» at the foot. Header, contents and bar keep the desktop's 24px padding down to `md` and drop to 16px below it.

Links have two hover styles (`Guide.tsx`): the contents in the sidebar and the mobile menu turn grey #808080 (`NAV_HOVER`); links in the page — the quick links, download rows and captions — get a hairline underline as set in Figma 4865:1061: black at 40%, 2.5% of the type size thick, 25% under the baseline, no skip ink, fading out over 0.25s (`UNDERLINE`, `LINK_HOVER`). A link inside body copy (`TEXT_LINK`) keeps that underline at 40% so it reads as a link, and it turns black on hover.

Plain "logo on a flat colour" figures are not images: `LogoPlate` in `Guide.tsx` renders `src/guide/UmoLogo.tsx` (inline SVG, `currentColor`) centred on a background, with the logo width given in Figma frame units.

Downloads live in `public/downloads/` and are listed by the `Assets` component in `Guide.tsx`: one row per file (↓, file name, size) or per page of the site (↗, title, path, e.g. the price-card constructor). Some pictures do what a row under them does (`PreviewLink` inside a `group/preview`, with that row passed to `Assets` as `preview`): the logo, the favicon and the UMO | Яндекс example download their SVG, the Ливрея and Прайс-карта previews (`Constructor`) open the constructor; pointing at the picture underlines its row. `umo-favicon.svg` / `.ico` are copies of `public/favicon.svg` / `.ico`: update them together. 1–3 rows stay in one column, 4+ split into two filled top to bottom, so list files grouped by item. Sizes come from the `virtual:download-sizes` module (`downloadSizesPlugin` in `vite.config.ts`), in КБ with a decimal comma; every row of a list gets one decimal as soon as one size is under 10, none otherwise. Each item ships as `<file>.svg` (black) and `<file>-png.zip` (black + white transparent PNGs). `umo-logo` (2400×480) sits under the Логотип figure, `umo-yandex` (the UMO | Яндекс lockup, 2080×400) under Кобрендинг, `umo-model-8` / `umo-model-5` (MODEL 8 / MODEL 5 lettering, 2400×280, exported from the `Vector` layers of Figma frame 4818:1961) under Леттеринг → Модели. The number plates `umo-plate-8` / `umo-plate-5` (5200×1120, the 520×112 mm plate) come in two colours that are separate designs rather than one mark on transparency, so they ship as one `<file>-svg.zip` holding `-black` (white on black) and `-white` (black on white), with no PNGs; the sources are `UMO-<n>_plate_b/_w.svg` from the Nameplate folder. In that list UMO 8 files come first so they fill the left column, under the UMO 8 pictures. Keep hairlines as filled rects, not stroked zero-width paths — ImageMagick drops the latter when rasterising. If the logo changes, update `umo-logo.svg` and `UmoLogo.tsx` together, then regenerate the PNGs, e.g. `magick -background none -density 360 umo-logo.svg -resize 2400x480 PNG32:umo-logo-black.png` (swap `fill="black"` for `white` for the white one), and re-zip with `zip -X -j`.

## Dealer livery (`/livery`)

Lettering for a dealer's demo car (Figma: UMO | Evrone, node 4021:2908): both sides and the rear window, with the dealer name, tagline and QR link editable. Every part but the UMO 8 lettering can be left out (Figma: UMO | Evrone, node 4900:4588): «QR-код», «Текст сверху» (the dealer name) and «Текст снизу» (the tagline) are checkboxes that label their fields (`OptionalField` in `src/ui/form.tsx`), and «Заднее стекло» adds the rear window; the sides are always in. What's off is in neither the preview, nor the decals, nor the spec. Without the QR (`noQr` and `withoutQr` in `layout.ts`) the sides are laid out anew (Figma: UMO | Evrone, node 4920:39): the lettering a third larger, 160 mm, making a 1100×500 mm sheet from the front edge, which stays where it was, so the door seam falls between UMO and 8 on the left and between U and M on the right; the texts sit at the front edge as before, and the bottom text can be 40 mm in three lines (up to 400 mm) or, with «Увеличить» at the end of its label row (`SizeSwitch`, Figma 4900:4662; «Уменьшить» switches back), 60 mm in two (up to 850 mm; `taglineLarge`), the switch showing only while the QR is off. The rear window has its QR column cut out instead: it centres its text and is cut down to the column (510 wide, as tall as the lettering and text), centred where the full sheet was. On the rear window the text is stacked (`stack` in `layout.ts`): the tagline follows the dealer name or takes its place, and the lettering with the text is centred vertically on the 250 mm, so leaving a text out leaves no hole; with everything on it matches the source. Its spec rows and lines on the text side are worked out from where the column lands (`stackDims` in `geometry.ts`), to half a millimetre: the lettering, the gap and the text zone, plus the margins above and under the column while the QR keeps the sheet at 250 (they're measured from its edges; the QR stays 250 so it scans from a distance); the last row takes up the rounding so the rows add up, and the sheet's full height is given on the other side. On the sides the spec also gives the distances to the body (~100 from the window line, ~150 to the sill moulding, measured at the front door's edge; ~125 / sheet / ~320 along the moulding), and the rows and grid lines of a text left out close up (`part` in `dims`, `withoutParts` in `geometry.ts`): the tagline's 120 + 120 become 240 while the QR still reaches the bottom. A side sheet is cut down to its content (`trimmed` in `geometry.ts`): without the top text it starts at the top of the QR and lettering, without the bottom text and the QR it ends under the lettering; it stays where it was on the body, so the strip cut off joins the distance to the body (~100 + 140 = ~240 to the window line, ~150 + 240 = ~390 to the moulding). Its spec dimensions are given separately in `noQr.dims`. The rear window takes the sides' text unless «Другой текст на стекле» is ticked (offered while the rear window and some text are on): then it gets its own fields, filled from the sides the first time. It reproduces the hand-made files in Yandex Disk `02 UMO/Livery/UMO 8`, with the decals in one file: the zip holds `UMO8_dealer-livery.pdf` (three pages: left and right side, 1280×500 mm each, and the rear window, 835×250 mm; the hand-made set has the rear window as a separate `_rearwindow.pdf`) and `00_UMO8_dealer-livery_spec.pdf` (the sheets on the car photos with dimensions in red; one point there is one millimetre on the car).

Everything is in millimetres in `src/livery/layout.ts`: per surface the QR, the UMO wordmark and model number, two text blocks (dealer, tagline) and the obstacles. Text is CoFo Sans Medium, 40 mm on 40 mm lines on the sides and 37.5 on the rear, anchored at the last line's baseline so a block grows upwards; these numbers were measured off the Illustrator sources and match them within half a millimetre, except the bottom tagline baselines, raised by 2 mm so a descender in the last line stays on the sheet. Lines wrap by ink width; words of one or two characters (prepositions, a `|`) stick to the next word. Pasted text is cleaned first (`clean` in `geometry.ts`): every kind of space becomes a plain one and zero-width marks go — the narrow no-break space has no glyph in CoFo Sans and glued words together — and a character the font lacks is an error. Limits: on the sides the dealer is up to 500 mm and two lines (it must stay clear of the door handle; 500 leaves it 13–23 mm), the tagline up to 400 mm and three lines (clear of the door seam); on the rear one dealer line (typed line breaks become spaces) and two tagline lines within 510 mm, three without a dealer name. Anything over the limit or within `clearance` of an obstacle turns red in the preview and blocks the download. The preview shows the sheets on the car photos. A checkbox at the foot of the sidebar adds an overlay that doesn't go into the files: «Показать размеры» (the spec's red dimensions, from `specMarks` in `geometry.ts`, which the spec PDF draws too). A second one, «Швы» (the door seam and handle), is commented out in `Livery.tsx`: the limits keep text off them and a sheet that touches them says so, so it only got in the way; `show=seams` in a link is ignored while it's out.

The obstacles — the seam between the doors and the front door handle — were taken from the spec mockup and are approximate; correct them in `leftObstacles` once there are real measurements (the right side mirrors them). The side and rear pictures (`src/assets/livery/umo8-side.webp`, `umo8-rear.webp`) are the photos from the spec PDF, cropped with known placement: the side covers 4800×2000 mm of the spec page from (0, 450), the rear 2280×2400 from (300, 250); `photo.x`/`photo.y` is where the sheet sits on them.

Cut files are vector only: every shape is a filled outline (text converted with opentype.js, the QR traced into merged contours so the plotter doesn't cut between modules), in the sources' colour C60 M40 Y40 K100, even-odd fill.

UMO 5 (`UMO5` in `layout.ts`; Figma: UMO | Evrone, node 3532:454 for the sides with the QR and the rear window, 4934:3338 for the sides without it) is laid out the same way with its own numbers, and the model switch picks between the two (`LIVERIES`). The sides are 1310×500: a 830 lettering column (UMO 600, 90, the 5 140 — the 5 of the number plate, `FIVE` in `logo.ts`), 120, the 360 QR column; text 40 mm on 42 mm lines, the dealer up to 550 and two lines (as without the QR, so a name that fits fits both ways), the tagline up to 420 and three, which wraps the default as Figma does and keeps it clear of the door seam. Without the QR the side is laid out anew like UMO 8's: the lettering 160 (1086,67 wide), the dealer name 40 mm up to 550, in two lines or one centred on them (`centred` on a text block; node 4934:3325), the tagline 40 mm in three lines up to 420 (node 4934:3341) or, with «Увеличить», 60 mm in two up to 850, as on UMO 8. The rear window is 650×200: QR 200, 50, a 400 column with the lettering 60 high and 30 mm text, stacked like UMO 8's. The car is white, so the side decals are black in the preview and the spec (`decal` on a surface; the cut file's colour is the same for both models); on the glass they stay white. The pictures come from the Figma frames at 0.5 px/mm: `umo5-side.webp` is the right side (4718×1680 mm, transparent around the car, the sheet's top at 682), mirrored for the left; `umo5-rear.webp` (2080×1980 mm) is the frame with the decal painted out of the darkened window, as only that frame has the window dark. The seam and front door handle in `right5Obstacles` were measured on that photo. Each model has its own default tagline («Попробуй гибрид…» / «Попробуй электрокар…»); switching models swaps it only while the field still holds the old model's default.

The guide's Ливрея section (Носители) shows `src/assets/guide/livery-umo8.webp`: the left side with the generator's default dealer («Автодом» over «Центр UMO») and tagline and no guides, rendered from the generator's cut file onto the spec photo (1824×912, the car 84% of the width). Regenerate it if the layout or defaults change.

## Plate frame (`/plate-frame`)

The dealer's line on a number plate frame (Figma: UMO | Evrone, node 4970:2419; guide section 4970:2280, anchor `plate-frame`): one line in the 501×21 mm print field of a standard 522×132 frame, «Центр UMO | » and the dealer's name: the prefix is fixed (`PREFIX` in `PlateFrame.tsx`), so every frame reads the same and nobody hunts for the bar, and only the name is typed (the «Дилер» field); a link with `text`, even empty (`/plate-frame?text`), opens a hidden mode with the whole line free, linked from nowhere, CoFo Sans Medium 18 mm, −1% tracking, with the case-sensitive forms on (`case`: the bar raised to the capitals; opentype.js doesn't apply the feature, so `setLine` substitutes the glyphs itself), the capitals' top 2.5 mm under the field's top (`BASELINE` in `src/plate/frame.ts`, from the font's 680-unit cap height; Figma has 3, raised by half a millimetre for optical balance, as the mostly lowercase line sat low), set from the left edge or centred. Text wider than the field or with a character the font lacks turns red and blocks the download. `UMO_plate-frame_501x21.pdf` is the field at 1:1, no bleed, the text in outlines filled with a spot colour named White (white ink for UV printing on the black frame; white on screen), over a black stand-in for the frame on a layer of its own, «Фон — не печатать», set not to print (an optional content group with PrintState OFF). ## Name tag (`/name-tag`)

A dealership employee's badge (Figma: UMO | Evrone, node 4021:2878), reproducing the hand-made source in Yandex Disk `02 UMO/Name Tag` (`UMO_name-tag.pdf`, its numbers measured off it in `tag.ts`): 70×25 mm, 4 mm corners and margins, the name and surname in CoFo Sans Medium 14 pt on 12 pt lines (baselines 7.65 and 11.88 mm), the position in Regular 9 pt on 10.8 pt lines (from 17.42 mm), the source's UMO logo 20×4 mm in the top right corner (`LOGO`, its outline copied from the PDF; the spec forbids redrawing it). The type size never shrinks: the name must stay 4 mm clear of the logo (38 mm), the surname, under the logo's bottom edge, may run to the right margin (62 mm; Александровская is 40, Шереметьева-Голицына 56); the surname takes a typed line break (Enter; two lines at most), and without one a double surname longer than that breaks after a hyphen (`splitSurname`: at the last hyphen leaving the first part fitting), either of which moves the position a line down (0.4 mm under the source's last baseline) and leaves it one line, the position wraps at 62 mm or at a typed line break, up to two lines. The page opens with empty fields; their placeholders (Имя, Фамилия, Должность) stand on the tag in grey and never go into the PDF, and a tag without a name and surname blocks the download. Anything over turns red and blocks the download. Two modes (no instructions on the page): «Вручную», where the sidebar edits one person at a time (titled, as their tag in the preview, with the name and surname, or the number while they're empty) — the selected tag, outlined in the preview; clicking another tag selects it, «Добавить» adds one and selects it, «Сбросить» empties the selected tag's fields, «Удалить» (while there's more than one) removes it and selects the next — and rows copied from a spreadsheet and pasted into any field fill in a row each (replacing the person pasted into if empty, the first of them selected); and «Из таблицы», where the template `public/downloads/UMO_name-tags_template.xlsx` (Имя, Фамилия, Должность, one example row; hand-written XML, zipped by a Python script) comes back filled in, dropped or picked as .xlsx, or its rows pasted anywhere on the page. The loaded rows become a list edited the same way as the manual one (each mode keeps its own list); a tag from the file keeps its row number in its title («строка 7») to find it there. Loading another file simply replaces the list, edits made on the page included. `src/nametag/table.ts` reads the first sheet itself (fflate + DOMParser: shared and inline strings), finds a header row by its titles in any column order, and keeps line breaks in a cell (Alt+Enter) as position line breaks; CSV isn't taken, as Russian Excel on Windows saves it in cp1251. The zip holds `UMO_name-tags.pdf` (a 70×25 page per person: the outline as a 0.5 pt stroke for the cut, logo and text as filled outlines, all C60 M40 Y40 K100 as in the source) and `00_UMO_name-tags_spec.txt`, the source's requirements for the maker without the steps the file now does itself (outlines). The preview is a flat neutral grey plate, not a silver render.

## Links with settings

The price card, livery and plate frame generators keep their settings in the page address, so a set-up card or livery can be sent as a link: «Копировать» in the sidebar copies it, as does the address bar; «Сбросить» clears it back to the defaults, keeping the model. The page reads them on load and writes them back with `history.replaceState` as they change; only what differs from the defaults goes in, and anything unknown or implausible falls back to the default. Messengers may encode a pasted link again (Telegram turns `%0A` into `%250A`), so `linkParams` decodes escapes left after decoding, up to twice. Price card: `model` (umo5), `trim`, `full` (seven digits, else the trim's price), `credit` (the credit price is on: `auto` follows the full price, seven digits are set by hand), `link`. Livery: `model` (umo5), `link`, `top`, `bottom` (the texts, line breaks as `%0A`; `bottom` is left out while it's the model's default), `off` (any of `qr,top,bottom,rear`), `rtop` / `rbottom` (the rear window's own text; either one turns «Другой текст на стекле» on), `show` (`dims,seams`) and `size=large` (the 60 mm bottom text). Plate frame: `name` (the dealer's name), `text` (the whole line, which also turns the hidden free mode on; the first links carried the line this way, so they open in it), `align=center`. The name tag generator keeps nothing in the address and has neither «Копировать» nor «Сбросить»: a staff list isn't sent as a link. Adding a setting means reading it in the page's initial state and writing it in its `useLinkState` call; keep the names stable, as links get sent around.

## Car photos

The car photos shown on the price card live at fixed paths so they can be swapped without touching code:

- `src/assets/umo5-car.jpg` — UMO 5
- `src/assets/umo8-car.jpg` — UMO 8

The exported PDF is printed at A3, and the car photo is meant to hold up at 300dpi — don't shrink it down to "web size." Target **3840×2160 for UMO5** and **3520×1980 for UMO8** (native resolution the car image container needs at 300dpi on an A3 sheet). Export as JPEG quality ~90; that lands each file around 1.5-2 MB. To update a photo, replace the file in place (keep the same filename).

CI (`.github/workflows/ci.yml`) and the deploy workflow both fail the build if any image under `src/` or `public/` exceeds 2.5 MB (and any `.mp4`/`.webm` 15 MB) — high enough for a real 300dpi print asset, low enough to catch a mistake like the raw 13 MB PNG that used to ship here and silently failed to load for users on slow connections.

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.
