# umo-brand

React + Vite + Tailwind CSS site for UMO brand materials: the brand guide at `/`, the price-card poster generator at `/price-card` (web preview + print-ready PDF export), the dealer livery generator at `/livery` (car preview + cut files), the number plate frame generator at `/plate-frame` (the strip printed under the plate, as a PDF), the name tag generator at `/name-tag` (staff badges, as a PDF) and the business card generator at `/business-card` (a dealership's staff cards, as a PDF). Deployed to `umo.autos` via GitHub Pages on every push to `main` (`.github/workflows/deploy.yml`).

## Development Server

Nothing runs automatically — start it yourself:

```bash
pnpm dev
```

This serves the app at `http://localhost:8443` (port set in `vite.config.ts`, not the Vite default). Hot reload is on; changes to source files show up immediately.

`pnpm dev:follow` (`scripts/dev-follow.mjs`) does the same and also pulls the current branch every 10 seconds (fast-forward only, reinstalling dependencies when the lockfile changes), so changes pushed to it show up in the open page without touching the terminal.

Not linked from anywhere. The font is `fonts/umo-sans/` (sources, build and its README); its Regular and Medium WOFF2 are copied to `public/fonts/UMOSans-*.woff2` and declared in `src/index.css` — copy them again after rebuilding the font
- `src/App.tsx` - Price-card generator page. Default full prices per model and trim are in `DEFAULTS`; the credit price follows the full one, a million less (`creditFor`), until it's set by hand, and is off by default (the «В кредит» checkbox): the card then shows one price under «Цена:» instead of «Без кредита:», as large as the headline (96 px), its figures standing on the QR code's bottom line — the dark modules' edge, a quiet-zone module above the code's box (`singlePriceTop` in `PriceCard` and `PriceCardPdf`; `creditPrice` is optional in both). The QR leads to the model's own page by default (`DEFAULT_URL`: https://umo.auto/umo8, https://umo.auto/umo5), and switching models swaps it while it's still the old model's page
- `src/Livery.tsx` - Dealer livery generator page (see "Dealer livery" below)
- `src/PlateFrame.tsx` - Number plate frame generator page (see "Plate frame" below)
- `src/NameTag.tsx` - Name tag generator page (see "Name tag" below)
- `src/BusinessCard.tsx` - Business card generator page (see "Business card" below)
- `src/card/` - The card's layout in mm, the phone format and the vCard (`card.ts`: `CARD`, `buildBack`, `formatPhone`, `vcard`), its PDF (`pdf.ts`) and the preview (`CardArt.tsx`)
- `src/ui/staff.tsx` - The staff list shared by the name tag and business card generators (`useStaff`: the manual and table modes, one person selected, «Добавить» / «Удалить» / «Сбросить», pasted rows, the dropped .xlsx, the fresh item whose empty fields aren't errors yet, the line leading through the items in work), with `TableSource`, `UploadArea`, `AddTile` and `Progress`

- `src/ui/form.tsx` - Sidebar controls shared by the generators (Figma 4844:6865 price card, 4900:4588 livery; the sidebar is 320 px plus a 1 px stroke): the header (`GeneratorHeader`: breadcrumbs «Бренд UMO» → `/` and «Носители» → `/#materials`, then the title, whose chevron is a transparent native `<select>` switching between the generators, listed alphabetically: Бейдж, Визитка, Ливрея, Прайс-карта, Рамка номера), segments, fields, the QR link field, a combobox (`ComboField`: a text field with suggestions in a popover under it, narrowed as you type; first used for the name tag's position), checkboxes (2 px tick, 8 px to the label), the size switch («Крупнее» / «Мельче» with arrows out or in, the same for the text and the QR), «Копировать» (the page address) and «Сбросить» (`LinkButtons`; reset keeps the model and brings everything else back to its defaults, which a reload can't, as the address keeps the settings) and the download button under them, spaced per Figma 4900:4595: 8 px from a label to its control, 16 px between groups (the gap of the column they sit in). On phones only the download button is pinned to the bottom of the screen
- `src/ui/share.ts` - Generator settings in the page address (`linkParams`, `useLinkState`), so a set-up card or livery is sent as a link
- `src/guide/Guide.tsx` - Brand guide page (see "Brand guide" below)
- `src/posters/` - Poster components: `PriceCard.tsx` (web preview) and `pdf/PriceCardPdf.tsx` (PDF export), sharing data from `cardData.ts`
- `src/data/` - The texts the generators suggest, in one place: the livery's taglines (`taglines.ts`), the name tag's positions (`positions.ts`) and the dealers (`dealers.ts`, from `dealers.json`)
- `src/data/dealers.json` - UMO dealers as umo.auto lists them (name, city, short address, coordinates, hours, models); their marketing names («UMO АГАТ Владимир», `DEALER_NAMES` in `src/data/dealers.ts`) are the suggestions in the livery's «Дилер» and the plate frame's «Дилер». Collected by `node scripts/fetch-dealers.mjs`, which opens a booking draft per model on umo.auto and switches it through every city (the page's `updateFormValues` server action, its id found in the page's scripts); run it by hand and review the changes with `git diff`
- `src/icons/` - SVG path data for the UMO logo/badges and small UI icons, imported directly by component name
- `src/index.css` - Global CSS entrypoint and Tailwind CSS v4 import
- `index.html` - Vite HTML shell containing the `#root` element and loading `src/main.tsx`. On iOS only, a script adds `maximum-scale=1` to the viewport: iOS Safari zooms into any field under 16px on focus and doesn't zoom back (the sidebar fields are 14px, the text edited on a tag or frame smaller), while still allowing a pinch zoom; on Android the same setting would block pinching
- `site.config.json` - Site title/description/favicon/OG-image/robots, applied to the built HTML by the `site-meta` Vite plugin. Icons in `public/` (Figma fav 4870:3556): `favicon.svg` and `favicon.ico` are the U module of the logo, white on a black tile — the full wordmark turns to mush at 16px. The tile is rounded in the icon itself: radius 1 on the 16 grid with 60% corner smoothing (Figma fav 4870:3579 has 8 on 40, too round at tab size), since Safari and Chrome show favicons as drawn and a square black tile looks cut out on a dark tab bar. The U is hinted: on a 16-unit grid its stems (2), bar (2) and edges sit on whole units, so it lands on whole pixels at 16, 32 and 48; the .ico's 16px frame keeps the hand-drawn U with mirrored corners and takes its rounded-corner alpha from the SVG; 32/48 are Chrome renders of the SVG at 768px, box-downscaled. `apple-touch-icon.png` (180) carries the whole UMO wordmark at 2/3 of the tile (120×24 at 30,78), as the app icon in Логотип на иконках
- `package.json` - Project dependencies and the Vite build, development, preview, and formatting scripts
- `vite.config.ts` - Vite configuration: React, Tailwind CSS v4, the `@` alias for `src`, and the `site-meta` plugin

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. This scaffold does not need a Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then add any `@font-face` rules and font-family defaults there.

## Brand guide (`/`)

`src/guide/Guide.tsx` is the web version of the UMO brand guide page from Figma ([UMO | Evrone, node 4810:686](https://www.figma.com/design/i6PdEDo72Vab0cAixG0nIz/UMO-%257C-Evrone?node-id=4810-686)). Text and layout are live code; every illustration is a Figma frame exported at 2x and saved as `src/assets/guide/<name>.webp` (cwebp `-q 90`), picked up automatically by `import.meta.glob`.

To refresh an illustration, re-export that frame at 2x and overwrite the file with the same name. Export the whole section Block and crop the frame out of it: frames that stretch inside a grid/flex parent come out of Figma's direct export at the wrong size (a mostly empty canvas).

Vector schemes (clear space, minimum size, co-branding, type specimens, model lettering) are SVG files in the same folder — `img()` prefers `<name>.svg` over `<name>.webp`. They are cut out of Figma SVG exports of the parent Body nodes by `scripts/split-figma-svg.py` (node ids and crop boxes are listed at the bottom of the script). Text inside them is outlined by Figma. The lettering pictures (`lettering-model8` / `lettering-model5`: MODEL lettering over its number plate) are laid out by the script's `assemble()` from separate layer exports instead, as those frames export stretched. Photos, logo misuse examples, app/social icons and model posters stay WebP.

The UMO 5 / UMO 8 ad banners in Ключевой образ are `Poster` components: a photo-only background (`<model>-<banner|square>-bg.webp`, about 3x the Figma frame) with the title, subtitle and `UmoYandexLockup` laid over it in container-width units, so text and lockup stay sharp at any size. The backgrounds were cut from the source photos using the layer geometry in Figma; the direct export of the banner photo layers is broken the same way as stretched frames.

On phones (below `md`) landscape photos — raster `Fig`s 2:1 and wider (`isWidePhoto`) — are cropped to 4:3 with `object-cover`; `focus` sets the crop's horizontal point in % where the subject isn't central (`umo5-kv`: 72, the car without the runner's sliver). An object on a flat background (`flat`, its colour: the livery, #f6f6f6) is fitted into the 4:3 frame whole instead, never cropped. SVG schemes stay whole. The Рамка номера card is 4:3 on phones too, its drawing enlarged to 130% so the plate fills 74% of the width.

Кобрендинг (Figma 4818:1328) is two columns, a scheme over its example, on 4:3 cards: the four 444×333 Figma cards exported as SVG (see the note in `scripts/split-figma-svg.py`: they export 684 wide, viewBox shifted by 120). The schemes open large on a click (`Zoom`, a lightbox: a click anywhere or Esc closes it, the page doesn't scroll under it).

Body copy (`Text`) takes its width from its length on the 12-column Figma grid: up to 150 characters 6 columns (432px), up to 300 — 8 (600px), longer — 9 (678px). Don't set widths by hand; texts paired side by side sit in a grid with `*:max-w-none` and fill their cells.

Vertical rhythm is fluid: `--spacing-section` (96px on a 375px phone → 216px at the 1440px Figma frame) and `--spacing-chapter` (144 → 288px) in `src/index.css`, used as `gap-section` between sections and as the extra top padding of a `Chapter`; don't hard-code breakpoint gaps between blocks. Each chapter is a `Chapter` (id, title, then its `Section`s). A section's opening picture goes above its heading, with the section anchor on the picture (Позиционирование, Фотография). Chapters stay two levels deep — chapter, then its sections. Пространства holds the brand's physical places (for now its intro with the dealership photo; the Дилерский центр section is drafted and commented out in `Guide.tsx`); Носители (anchor `materials`) the templated media (Ливрея, Прайс-карта, Рамка номера, Бейдж, later leaflets and the like), as Porsche splits Spaces from Analog media. Носители is a two-column intro and a grid of the media (`Carriers`, Figma 4844:6695), with no section per medium: each card is the medium's picture right over its ↗ row to the constructor and carries its anchor (`livery`, `price-card`, `plate-frame`, `name-tag`, the sidebar's sub-items); pictures 2:1 and wider span the width, the rest pair up, a narrow one moving up next to an unpaired one. The media are one list, `MEDIA_LIST` in `Guide.tsx`; `packMedia` turns it into the order the cards actually stand in (`MEDIA`), and both the grid and the sidebar's sub-items follow it. A new medium is one entry there. Anchor ids sit on an empty marker above the title, so keep new chapters inside `Chapter` rather than a bare `<h2 id>`. Links to the guide have gone out, so when an anchor id changes, add the old one to `OLD_ANCHORS` in `Guide.tsx`: it is redirected to the new id on load and on a hash change.

The first screen follows Figma 4893:3846 and 4897:4565 (prototype 4921:2352): on `lg`+ the hero (`Hero` in `Guide.tsx`) is fixed full-width behind the page, which starts a strip above the bottom of the screen (`--strip`, set by `useHeroStrip`: 286px at 1440), so the first screen shows the photo, the 200px logo, the «Содержание» row, the statement and the quick links under it (Стандарты → `#positioning`, the way into the whole guide from its first page, which lands its picture 24px under the top of the screen from `lg` — `lg:scroll-mt-6`; Носители → `#materials`, 48px below the statement; no link to the official site); scrolling, the page slides up over the photo. The sidebar's toggle row is fixed to the bottom of the screen (CSS, not script: moved by script it lagged the scroll a frame and shook); until the page docks at the top, `useHeroReveal` fades the contents in over the first 160px of scroll, so they unroll between logo and row; the photo stays still (no parallax: it cheapened the curtain), the logo shrinks with the scroll from 200px wide to its usual 120 (24 high) by the time the page docks, and the row does what it says anywhere, on the first screen also scrolling the page up to the top. The logo scrolls smoothly to the very top (`toTop`), photo included; «Платформа бренда» lands the page's top edge at the top of the screen (`lg:scroll-mt-[calc(24px-0.164em)]` on the statement, the body's padding above it plus its own margin), so no strip of the photo shows. The statement is aligned optically by CoFo Sans's metrics: the body's 16px on top plus `lg:mt-[calc(8px-0.164em)]` put its capitals level with the top of the logo at any size, and the strip is sized so the quick links share a line with the toggle row, however many lines the statement wraps to. Below `lg` the film is simply the first thing on the page, above the header, and takes what the first screen has left above the header, statement and quick links (`--mstrip`, measured by `useHeroStrip`) and the bottom bar with a gap over it, so the first section of the guide starts below the fold; it is never less than half the screen's width (a phone held sideways). The hero is the UMO test-drive film (source `02 UMO/Site Video/Test Drive/` on Yandex Disk), looped and muted: `src/assets/guide/hero.mp4` is `UMO_test-drive_1080.mp4` byte for byte (H.264, 12 MB) and `hero-720.mp4` is `UMO_test-drive_720.mp4` (1280×720, 6.2 MB), both already fast-start and silent — don't re-encode them, they were set up by hand — with their first frame as `hero-poster.webp`. The 1080p plays by default and the 720p on a slow connection: at once where the browser reports the speed (Network Information API in Chrome, Edge, Android: `effectiveType` 3G or slower; not `downlink`, which Chrome guesses from the first requests and reads far too low then), and in any browser (Safari has no such API) when the 1080p hasn't buffered enough to play 3 s after the page opens. It plays only while some of it is on screen, stopping once the page has slid over it whole and going on from that frame when it shows again; with reduced motion or data saving on, the still `hero.webp` (woman by UMO 8) stands in. CI and the deploy fail on any video over 15 MB. Navigation follows Figma section TOC (node 4865:1079). The hero at the top of the page is not in the list: the logo leads there. Платформа бренда (the brand foundations: positioning, vision, mission, audience and voice) has no title of its own: the statement under the hero («Автомобильный бренд, созданный в технологическом партнёрстве с Яндексом»: from `lg` 60px in the 912px Figma column, scaled with the column below that — `min(60px, 6.58cqw)` — so it wraps the same three lines at any width; no «UMO —»: the logo stands right beside it) stands in for it and carries the `brand` anchor, so it isn't a `Chapter`. On `lg`+ the sidebar lists chapters with only the one you're reading open; the space between items is the links' own padding (chapters 8px above and under, items 4px, the last item of a chapter 8px under it), not gaps, so the whole list is clickable with the same rhythm as before (Figma 4865:1031), and the list's -8px top and bottom margins tuck the first and last chapters' padding under the logo and the toggle row (4865:1025); the «Содержание / Свернуть» row (`TocToggle`, menu and cross icons from `src/icons/toc.ts`, the same as on the mobile bar) is pinned to the bottom of the screen, so it doesn't move as the open chapter changes the list's height. The choice is remembered in `localStorage`. When the list is taller than the screen, the sidebar scrolls itself to keep the item you're reading in view (`useActiveInView`). Below `lg` the header holds just the logo; a bar fixed at the bottom shows a menu icon and the title of the heading you're reading (any level, from `NAV`; «Платформа бренда» on the hero above it) and opens the full, expanded contents between header and bar, with «Свернуть» at the foot. Header, contents and bar keep the desktop's 24px padding down to `md` and drop to 16px below it.

Links have two hover styles (`Guide.tsx`): the contents in the sidebar and the mobile menu turn grey #808080 (`NAV_HOVER`); links in the page — the quick links, download rows and captions — get a hairline underline as set in Figma 4865:1061: black at 40%, 2.5% of the type size thick, 25% under the baseline, no skip ink, fading out over 0.25s (`UNDERLINE`, `LINK_HOVER`). A link inside body copy (`TEXT_LINK`) keeps that underline at 40% so it reads as a link, and it turns black on hover.

Plain "logo on a flat colour" figures are not images: `LogoPlate` in `Guide.tsx` renders `src/guide/UmoLogo.tsx` (inline SVG, `currentColor`) centred on a background, with the logo width given in Figma frame units.

Downloads live in `public/downloads/` and are listed by the `Assets` component in `Guide.tsx`: one row per file (↓, file name, size) or per page of the site (↗, title, path, e.g. the price-card constructor). Some pictures do what a row under them does (`PreviewLink` inside a `group/preview`, with that row passed to `Assets` as `preview`): the logo, the favicon and the UMO | Яндекс example download their SVG, the Ливрея and Прайс-карта previews (`Constructor`) open the constructor; pointing at the picture underlines its row. `umo-favicon.svg` / `.ico` are copies of `public/favicon.svg` / `.ico`: update them together. 1–3 rows stay in one column, 4+ split into two filled top to bottom, so list files grouped by item. Sizes come from the `virtual:download-sizes` module (`downloadSizesPlugin` in `vite.config.ts`), in КБ with a decimal comma; every row of a list gets one decimal as soon as one size is under 10, none otherwise. Each item ships as `<file>.svg` (black) and `<file>-png.zip` (black + white transparent PNGs). `umo-logo` (2400×480) sits under the Логотип figure, `umo-yandex` (the UMO | Яндекс lockup, 2080×400) under Кобрендинг, `umo-model-8` / `umo-model-5` (MODEL 8 / MODEL 5 lettering, 2400×280, exported from the `Vector` layers of Figma frame 4818:1961) under Леттеринг → Модели. The number plates `umo-plate-8` / `umo-plate-5` (5200×1120, the 520×112 mm plate) come in two colours that are separate designs rather than one mark on transparency, so they ship as one `<file>-svg.zip` holding `-black` (white on black) and `-white` (black on white), with no PNGs; the sources are `UMO-<n>_plate_b/_w.svg` from the Nameplate folder. In that list UMO 8 files come first so they fill the left column, under the UMO 8 pictures. Keep hairlines as filled rects, not stroked zero-width paths — ImageMagick drops the latter when rasterising. If the logo changes, update `umo-logo.svg` and `UmoLogo.tsx` together, then regenerate the PNGs, e.g. `magick -background none -density 360 umo-logo.svg -resize 2400x480 PNG32:umo-logo-black.png` (swap `fill="black"` for `white` for the white one), and re-zip with `zip -X -j`.

## Dealer livery (`/livery`)

Lettering for a dealer's demo car (Figma: UMO | Evrone, node 4021:2908): both sides and the rear window, with the dealer name, tagline and QR link editable. Every part but the UMO 8 lettering can be left out (Figma: UMO | Evrone, node 4900:4588): «QR-код», «Дилер» (the dealer name) and «Слоган» (the tagline; the fields were «Текст сверху» and «Текст снизу», renamed for what they hold, which also explains their different suggestions) are checkboxes that label their fields (`OptionalField` in `src/ui/form.tsx`), and «Заднее стекло» adds the rear window, off by default (it was on, and in the way for most cars); the sides are always in. What's off is in neither the preview, nor the decals, nor the spec. Without the QR (`noQr` and `withoutQr` in `layout.ts`) the sides are laid out anew (Figma: UMO | Evrone, node 4920:39): the lettering a third larger, 160 mm, making a 1100×500 mm sheet from the front edge, which stays where it was, so the door seam falls between UMO and 8 on the left and between U and M on the right; the texts sit at the front edge as before, and the bottom text can be 40 mm in three lines (up to 400 mm) or, with «Крупнее» at the end of its label row (`SizeSwitch`, Figma 4900:4662; «Мельче» switches back), 60 mm in two (up to 850 mm; `taglineLarge`), the switch showing only while the sides are laid out this way. The QR can be made small with «Мельче» at the end of its label row (the same `SizeSwitch`; «Крупнее» switches back; Figma 4991:10211 for UMO 8, 4985:10180 for UMO 5): the sides are then laid out as without the QR, with a 160 mm QR, as tall as the lettering and level with it, 100 mm behind the model number at the rear end of the sheet (`smallQr` in `layout.ts`), so the sheet is 260 longer towards the rear (1360 on UMO 8, 1346,67 on UMO 5), its front edge staying where it was, the spec's dimensions following; both tagline sizes are offered with it. Small or large is the user's choice, not tied to the texts: a small QR scans only up close (roughly from ten times its side, ~1,5 m against ~3,5 m). The rear window keeps its QR. The rear window has its QR column cut out instead: it centres its text and is cut down to the column (510 wide, as tall as the lettering and text), centred where the full sheet was. On the rear window the text is stacked (`stack` in `layout.ts`): the tagline follows the dealer name or takes its place, so leaving a text out leaves no hole, and the sheet is cut down to the column (from the top of the lettering to the last descender), centred where the full sheet was; with everything on it matches the source. The QR is as tall as the column (`sized` in `geometry.ts`): with all the text the column fills the 250 and the QR stays 250; with less it shrinks with it (UMO 8 without the dealer name: 197,5; without any text: the lettering's 75), staying at the start with the same gap after it, the sheet narrowing by as much, centred too. Before, the QR kept 250 for scanning from a distance and the column was centred on it, which left the QR sticking out over a short column. Its spec rows and lines on the text side are worked out from where the column lands (`stackDims` in `geometry.ts`), to half a millimetre: the lettering, the gap and the text zone, plus margins above and under the column where it is shorter than the sheet; the last row takes up the rounding so the rows add up, and the sheet's full height is given on the other side. On the sides the spec also gives the distances to the body (~100 from the window line, ~150 to the sill moulding, measured at the front door's edge; ~125 / sheet / ~320 along the moulding), and the rows and grid lines of a text left out close up (`part` in `dims`, `withoutParts` in `geometry.ts`): the tagline's 120 + 120 become 240 while the QR still reaches the bottom. A side sheet is cut down to its content (`trimmed` in `geometry.ts`): without the top text it starts at the top of the QR and lettering, without the bottom text and the QR it ends under the lettering; it stays where it was on the body, so the strip cut off joins the distance to the body (~100 + 140 = ~240 to the window line, ~150 + 240 = ~390 to the moulding). Its spec dimensions are given separately in `noQr.dims`. The rear window carries the sides' slogan and dealer name (in one line). Ticked, it shows under it, not indented: «Слоган на стекле» (left off the glass or not) with its field, following the sides' slogan until it's edited (as the price card's credit price follows the full one), and «Дилер на стекле» (left off or not; a different name had no reason to exist). Turning the rear window off forgets its settings, so it comes back carrying the sides' texts. (Tried before: «Другой текст на стекле» with both texts of its own; four checkboxes in a row while the glass was on by default; its options behind «Настроить» or «Изменить» / «По умолчанию», needless once the glass is off by default and only those who want it see them; no slogan of its own at all.) It reproduces the hand-made files in Yandex Disk `02 UMO/Livery/UMO 8`, with the decals in one file: the zip holds `UMO8_dealer-livery.pdf` (three pages: left and right side, 1280×500 mm each, and the rear window, 835×250 mm; the hand-made set has the rear window as a separate `_rearwindow.pdf`) and `00_UMO8_dealer-livery_spec.pdf` (the sheets on the car photos with dimensions in red; one point there is one millimetre on the car).

Everything is in millimetres in `src/livery/layout.ts`: per surface the QR, the UMO wordmark and model number, two text blocks (dealer, tagline) and the obstacles. ## Obscene words

The plate frame, name tag, business card and livery generators refuse obscene words (`src/ui/profanity.ts`, `hasProfanity`), so a screenshot of «Центр UMO | <мат>» from umo.autos can't happen: the check adds an issue in `buildStrip`, `buildTag` (per field: «Имя: недопустимое слово») and `setText` (on the lines holding the word, so only they turn red; all of a text's lines when the word is spaced out across them), which turns the text red and blocks the download like any other error. The word itself is never shown, and nothing is starred out. It catches the Russian мат roots (хуй, пизд, еб at the start of a word or after a prefix, блядь/бля, муд-, пидор, залуп, манда, гондон, шлюха, сука) and a few English ones (fuck, cunt, shit, bitch…), seen through disguises: case, ё, Latin and digit look-alikes (a, c, e, o, p, x, y, k, m, h, t, b→в; 0, 1, 3, 4, 6, @), letters spaced, dotted or hyphenated apart, a star for a letter. Roots that occur inside ordinary words are anchored so хлеб, небо, себе, вебинар, рубля, гребля, мандарин, команда, мудрый, страхуем, гондола and Scunthorpe pass. Jokes and rude but printable words («Шляпа полная», хер, жопа) are deliberately not caught. Client-side only, no library: extend the lists in `profanity.ts` and check ordinary words against them.

## Links with settings

The price card, livery and plate frame generators keep their settings in the page address, so a set-up card or livery can be sent as a link: «Копировать» in the sidebar copies it, as does the address bar; «Сбросить» clears it back to the defaults, keeping the model. The page reads them on load and writes them back with `history.replaceState` as they change; only what differs from the defaults goes in, and anything unknown or implausible falls back to the default. Messengers may encode a pasted link again (Telegram turns `%0A` into `%250A`), so `linkParams` decodes escapes left after decoding, up to twice. Price card: `model` (umo5), `trim`, `full` (seven digits, else the trim's price), `credit` (the credit price is on: `auto` follows the full price, seven digits are set by hand), `link` (left out while it's the model's own page). Livery: `model` (umo5), `link`, `top`, `bottom` (the texts, line breaks as `%0A`; `bottom` is left out while it's the model's default), `off` (any of `qr,top,bottom,rdealer,rslogan`; `rdealer` and `rslogan` leave the dealer or the slogan off the rear window), `rear=on` (the rear window, off by default; links from when it was on by default open without it, and their `off=rear` is ignored), `rbottom` (the rear window's slogan once it differs from the sides'; `rtop`, its own dealer name, is no longer read, so such links open with the sides' name), `show` (`dims,seams`), `size=large` (the 60 mm bottom text) and `qr=small` (the small QR on the sides). Plate frame: `name` (the dealer's name), `text` (the whole line, which also turns the hidden free mode on; the first links carried the line this way, so they open in it), `align=center`. The name tag generator keeps nothing in the address and has no «Копировать»: a staff list isn't sent as a link. Adding a setting means reading it in the page's initial state and writing it in its `useLinkState` call; keep the names stable, as links get sent around.

## Car photos

The car photos shown on the price card live at fixed paths so they can be swapped without touching code:

- `src/assets/umo5-car.jpg` — UMO 5
- `src/assets/umo8-car.jpg` — UMO 8

The exported PDF is printed at A3, and the car photo is meant to hold up at 300dpi — don't shrink it down to "web size." Target **3840×2160 for UMO5** and **3520×1980 for UMO8** (native resolution the car image container needs at 300dpi on an A3 sheet). Export as JPEG quality ~90; that lands each file around 1.5-2 MB. To update a photo, replace the file in place (keep the same filename).

CI (`.github/workflows/ci.yml`) and the deploy workflow both fail the build if any image under `src/` or `public/` exceeds 2.5 MB (and any `.mp4`/`.webm` 15 MB) — high enough for a real 300dpi print asset, low enough to catch a mistake like the raw 13 MB PNG that used to ship here and silently failed to load for users on slow connections.

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.
