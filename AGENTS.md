# umo-brand

React + Vite + Tailwind CSS site for UMO brand materials: the brand guide at `/`, the price-card poster generator at `/price-card` (web preview + print-ready PDF export), the dealer livery generator at `/livery` (car preview + cut files), the number plate frame generator at `/plate-frame` (the strip printed under the plate, as a PDF), the name tag generator at `/name-tag` (staff badges, as a PDF), the business card generator at `/business-card` (a dealership's staff cards, as a PDF), the price tag generator at `/price-tag` (tags for the small goods, eight to an A4 sheet, as a PDF) and the hours sign generator at `/hours-sign` (the dealership's opening hours plate, as a PDF). Deployed to `umo.autos` via GitHub Pages on every push to `main` (`.github/workflows/deploy.yml`).

This file describes the project as it is now. The history of decisions (what was tried and dropped) lives in commit messages, not here; keep only a short «not X» where a dropped option is likely to be proposed again.

## Development Server

Nothing runs automatically — start it yourself:

```bash
pnpm dev
```

This serves the app at `http://localhost:8443` (port set in `vite.config.ts`, not the Vite default). Hot reload is on.

`pnpm dev:follow` (`scripts/dev-follow.mjs`) does the same and also pulls the current branch every 10 seconds (fast-forward only, reinstalling dependencies when the lockfile changes), so changes pushed to it show up in the open page.

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';`. Use Tailwind utility classes directly in JSX and put global CSS or Tailwind v4 theme customization in `src/index.css`. No Tailwind config file or PostCSS config.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/index.css`. Keep CSS `@import` statements first, then any `@font-face` rules and font-family defaults.

## Brand guide (`/`)

`src/guide/Guide.tsx` is the web version of the UMO brand guide page from Figma ([UMO | Evrone, node 4810:686](https://www.figma.com/design/i6PdEDo72Vab0cAixG0nIz/UMO-%257C-Evrone?node-id=4810-686)). Text and layout are live code; every illustration is a Figma frame exported at 2x and saved as `src/assets/guide/<name>.webp` (cwebp `-q 90`), picked up automatically by `import.meta.glob`.

To refresh an illustration, re-export that frame at 2x and overwrite the file with the same name. Export the whole section Block and crop the frame out of it: frames that stretch inside a grid/flex parent come out of Figma's direct export at the wrong size (a mostly empty canvas).

Vector schemes (clear space, minimum size, co-branding, type specimens, model lettering) are SVG files in the same folder — `img()` prefers `<name>.svg` over `<name>.webp`. They are cut out of Figma SVG exports of the parent Body nodes by `scripts/split-figma-svg.py` (node ids and crop boxes at the bottom of the script). Text inside them is outlined by Figma. The lettering pictures (`lettering-model8` / `lettering-model5`: MODEL lettering over its number plate) are laid out by the script's `assemble()` from separate layer exports, as those frames export stretched. Photos, logo misuse examples, app/social icons and model posters stay WebP.

### Structure and rhythm

Each chapter is a `Chapter` (id, title, then its `Section`s). Chapters stay two levels deep — chapter, then its sections. A section's opening picture goes above its heading, with the section anchor on the picture. Anchor ids sit on an empty marker above the title, so keep new chapters inside `Chapter` rather than a bare `<h2 id>`. Links to the guide have gone out, so when an anchor id changes, add the old one to `OLD_ANCHORS` in `Guide.tsx`: it is redirected to the new id on load and on a hash change.

Body copy (`Text`) takes its width from its length on the 12-column Figma grid: up to 150 characters 6 columns (432px), up to 300 — 8 (600px), longer — 9 (678px). Don't set widths by hand (the one exception, `wide`, gives Контакты 9 columns); texts paired side by side sit in a grid with `*:max-w-none` and fill their cells.

Vertical rhythm is fluid: `--spacing-section` (96px on a 375px phone → 216px at the 1440px Figma frame) and `--spacing-chapter` (144 → 288px) in `src/index.css`, used as `gap-section` between sections and as the extra top padding of a `Chapter`; don't hard-code breakpoint gaps between blocks.

Below 520 px landscape photos — raster `Fig`s 2:1 and wider (`isWidePhoto`) — are cropped to 4:3 with `object-cover`; `focus` sets the crop's horizontal point in % where the subject isn't central (`umo5-kv`: 72). An object on a flat background (`flat`, its colour: the livery, #f6f6f6) is fitted into the 4:3 frame whole instead. SVG schemes stay whole; the Логотип plate and the clear-space scheme alone are 4:3 on phones (`phone43`), the scheme fitted whole on its grey. From 520 px some pairs already stand side by side: the logo-on-icons pictures, Леттеринг → Модели (its downloads from 560, `early` on `Assets`) and Сделано в Москве. Below `md` pictures stand 16 px apart, as the page's side gutter, across and down, and so do a picture and the download rows under it (24 from `md`).

### First screen

The first screen follows Figma 4893:3846 and 4897:4565 (prototype 4921:2352). On `lg`+ the hero (`Hero`) is fixed full-width behind the page, which starts a strip above the bottom of the screen (`--strip`, set by `useHeroStrip`: 286px at 1440), so the first screen shows the photo, the 200px logo, the «Содержание» row, the statement and the quick links under it (Платформа → `#positioning`, landing its picture 24px under the top of the screen from `lg` — `lg:scroll-mt-6`; Материалы для дилеров → `#materials`; no link to the official site), 48px below the statement; scrolling, the page slides up over the photo. The sidebar's toggle row is fixed to the bottom of the screen in CSS, not script (moved by script it lagged the scroll a frame). Until the page docks at the top, `useHeroReveal` fades the contents in over the first 160px of scroll; the photo stays still (no parallax), the logo shrinks with the scroll from 200px wide to its usual 120 by the time the page docks, and the row does what it says anywhere, on the first screen also scrolling the page up to the top; on the first screen, where the contents are under half faded in, it says «Содержание» even while the list is expanded, and a click takes the page up with the list open. The logo scrolls smoothly to the very top (`toTop`). «Платформа бренда» lands the page's top edge at the top of the screen (`lg:scroll-mt-[calc(24px-0.164em)]` on the statement). The statement is aligned optically by CoFo Sans's metrics: the body's 16px on top plus `lg:mt-[calc(8px-0.164em)]` put its capitals level with the top of the logo at any size, and the strip is sized so the quick links share a line with the toggle row, however many lines the statement wraps to.

Below `lg` the film is the first thing on the page, above the header, and takes what the first screen has left above the header, statement, quick links and the bottom bar with a gap over it (`--mstrip`, measured by `useHeroStrip`), so the first section starts below the fold; it is never less than half the screen's width.

The hero is the UMO test-drive film (source `02 UMO/Site Video/Test Drive/` on Yandex Disk), looped and muted: `src/assets/guide/hero.mp4` is `UMO_test-drive_1080.mp4` byte for byte (H.264, 12 MB) and `hero-720.mp4` is `UMO_test-drive_720.mp4` (1280×720, 6.2 MB), both already fast-start and silent — don't re-encode them — with their first frame as `hero-poster.webp`. The 1080p plays by default and the 720p on a slow connection: at once where the browser reports the speed (Network Information API: `effectiveType` 3G or slower; not `downlink`, which Chrome reads far too low at first), and in any browser when the 1080p hasn't buffered enough to play 3 s after the page opens. It plays only while some of it is on screen; with reduced motion or data saving on, the still `hero.webp` stands in. CI and the deploy fail on any video over 15 MB.

### Navigation

Navigation follows Figma section TOC (node 4865:1079). On `lg`+ the sidebar is 320 px, from `xl` a third of the screen and the page the other two thirds, with no cap. The hero isn't in the list: the logo leads there. The choice is remembered in `localStorage`. When the list is taller than the screen, the sidebar scrolls itself to keep the item you're reading in view (`useActiveInView`).

Below `lg` the header holds just the logo; a bar fixed at the bottom shows a menu icon and the title of the heading you're reading (any level, from `NAV`), «Содержание» on the first screen, and opens the full, expanded contents as a sheet from the bottom, 60% of the screen at most, its top corners 16 px round, over the page dimmed at 40% (a tap on it closes it), the list scrolling inside it and opened at the chapter you're reading, with «Свернуть» at the foot. Header, contents and bar keep 24px padding down to `md` and 16px below it.

Links have two hover styles: the contents in the sidebar and the mobile menu turn grey #808080 (`NAV_HOVER`); links in the page — the quick links, download rows and captions — get a hairline underline as set in Figma 4865:1061: black at 40%, 2.5% of the type size thick, 25% under the baseline, no skip ink, fading out over 0.25s (`UNDERLINE`, `LINK_HOVER`). A link inside body copy (`TEXT_LINK`) keeps that underline at 40% so it reads as a link, and turns black on hover.

Plain "logo on a flat colour" figures are not images: `LogoPlate` renders `src/guide/UmoLogo.tsx` (inline SVG, `currentColor`) centred on a background, with the logo width in Figma frame units.

## Files dropped back

The price tag, business card, name tag and hours sign generators open their own downloads again: the PDF carries what it was made from as JSON in its document info (`writePdfData` in `src/ui/pdfDataWrite.ts`, under `UMOPriceTags`, `UMOBusinessCards` — dealership, QR link, «Обложка у всех», «Метки реза», the staff — `UMONameTags` and `UMOHoursSign`), saved without object streams so `readPdfData` (`src/ui/pdfData.ts`) finds it with no PDF parser; dropped on the page or picked in the upload («Загрузить таблицу или PDF», the name tag's «Загрузить таблицу или ZIP»), it replaces the list as a table does. Any other PDF is said to have no cards. The price card, livery and plate frame don't: their settings are in the link.

## Names

The name tag and business card take only letters in a name and surname, with spaces, hyphens and dashes, apostrophes (Д'Артаньян) and dots (initials) (`nameFault` in `src/ui/names.ts`): a digit is «Имя: цифры», another sign «Фамилия: лишние знаки «@»», an error red on the item and blocking the download, never taken out quietly (it's most often a table pasted askew).

## Obscene words

The plate frame, name tag, business card and livery refuse obscene words (`src/ui/profanity.ts`, `hasProfanity`): the check adds an issue in `buildStrip`, `buildTag` (per field: «Имя: недопустимое слово») and `setText` (on the lines holding the word; all of a text's lines when the word is spaced out across them), turning the text red and blocking the download. The word itself is never shown, nothing is starred out. It catches the Russian мат roots (хуй, пизд, еб at the start of a word or after a prefix, блядь/бля, муд-, пидор, залуп, манда, гондон, шлюха, сука), vulgar words out of place on a dealer's frame or badge (грёбаный, жопа, говно, дерьмо, срать, ссать, хер, дрочить, пердеть, трахать, сиськи, шалава, мразь, ублюдок, чмо) and a few English ones (fuck, cunt, shit, bitch…), through disguises: case, ё, Latin and digit look-alikes (a, c, e, o, p, x, y, k, m, h, t, b→в; 0, 1, 3, 4, 6, @), letters spaced, dotted or hyphenated apart, a star for a letter. Roots that occur inside ordinary words are anchored so хлеб, небо, себе, вебинар, рубля, гребля, гребень, мандарин, команда, мудрый, страхуем, гондола, сравнение, сруб, ссылка, ссуда, SsangYong, Херсон, херес, страх, трахея and Scunthorpe pass. Jokes and plain insults («Шляпа полная», дурак, лох, задница) are deliberately not caught. Client-side only, no library: extend the lists and check ordinary words against them.

## Links with settings

The price card, livery, plate frame and hours sign keep their settings in the page address, so a set-up result is sent as a link («Поделиться», or the address bar). The page reads them on load and writes them back with `history.replaceState`; only what differs from the defaults goes in, and anything unknown or implausible falls back to the default. Messengers may encode a pasted link again (Telegram turns `%0A` into `%250A`), so `linkParams` decodes escapes left after decoding, up to twice. Keep the names stable, as links get sent around; adding a setting means reading it in the page's initial state and writing it in its `useLinkState` call.

- Price card: `model` (umo8; UMO 5 is the default in both models' generators and comes first in the switch, Figma 5015:11121), `trim`, `full` (seven digits, else the trim's price), `credit` (on: `auto` follows the full price, seven digits are set by hand), `link` (left out while it's the model's page); these are the first card's, the next cards' carry their number (`model2`, `full3`, `link2`) and `cards` says how many (up to 20; left out for one).
- Livery: `model` (umo8), `link`, `top`, `bottom` (line breaks as `%0A`; `bottom` left out while it's the model's default), `off` (any of `qr,top,bottom,rdealer,rslogan`; the last two leave the dealer or slogan off the rear window; `off=rear` is ignored), `rear=on`, `rbottom` (the rear window's slogan once it differs from the sides'; `rtop` is no longer read), `show` (`dims,seams`), `size=large` (the 60 mm bottom text), `qr=small`.
- Plate frame: `name`, `text` (the whole line, which also turns the free mode on), `align=center`.
- Hours sign: `from`, `to`, `name`, `address` (once it isn't the dealer's), `phone`, `site` (once edited).

## Image sizes

CI (`.github/workflows/ci.yml`) and the deploy workflow fail the build if any image under `src/` or `public/` exceeds 2.5 MB (and any `.mp4`/`.webm` 15 MB).

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.
